# memorex Agent Guide

## Project Shape

`memorex` is a TypeScript CLI, MCP server, and Claude Code hook set for passive local memory. Runtime behavior lives under `src/`; tests live under `src/__tests__/`; hook build output is generated by `scripts/build-hooks.mjs`.

Keep this repo focused on memory storage, retrieval, hook injection, diagnostics, analytics, and import/export behavior. Do not introduce unrelated app UI, remote services, cloud sync, or changes to Claude/Codex global config unless the task explicitly asks for it.

## Setup

Use Node 18 or newer.

```bash
npm install
```

For a one-command local readiness check:

```bash
./init.sh
```

## Verification

Before calling implementation work complete, run:

```bash
npm run typecheck
npm test
npm run lint
```

Run `npm run build` when changing the CLI entrypoint, hook source files, TypeScript config, package exports, or build scripts.

## Work Rules

- Prefer narrow changes that match the existing TypeScript/Vitest style.
- Keep runtime APIs stable unless the task explicitly calls for an interface change.
- Treat `~/.memorex/memories.db`, user vaults, `.env` files, and shell/browser state as private local data; never copy secrets into docs, tests, or logs.
- Do not edit generated `dist/` output directly.
- Do not rewrite unrelated documentation or changelog entries while doing feature work.
- Update `feature_list.json` for active feature work and `claude-progress.md` when handing off non-trivial context.

## Done Criteria

Work is done only when the behavior is implemented or intentionally documented as non-code harness metadata, the relevant verification commands pass or blockers are recorded, and any changed agent-facing workflow files accurately describe the current repo.
